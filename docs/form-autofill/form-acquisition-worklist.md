# Form-acquisition worklist (from the corridor-content harvest)

_Generated by `scripts/form_acquisition_worklist.py` — the plan's Build A §3.1 backlog ([form-fill integration plan](../plans/form-fill-integration-build-plan.md)). The harvested `form_name` field is the authoritative list of forms each corridor needs._

## Summary

- **498** distinct (corridor, form) pairs across **35** corridors.
- **57** look like a **coded government PDF** (a form code → a blank PDF may exist to fill) — the acquisition candidates.
- **86** are **online portals / e-filing / apps** — no blank PDF to pre-fill (out of scope for AcroForm fill).
- **355** are un-coded / generic (bank KYC, "varies by provider", notifications) — assess case by case.

> Classification is heuristic (keyword-based) and only narrows the search — a coded name is not proof of a fillable AcroForm (most gov PDFs are flattened; France's CERFA `*05` was the one fillable one of five checked). Each candidate still needs the AcroForm check from ACROFORM-FEASIBILITY-DE-FR.md, fetched in a real browser. **Exemplar done:** `FR_cerfa_14571_v2024` (France-Visas CERFA 14571-*05).
