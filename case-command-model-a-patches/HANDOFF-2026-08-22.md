## C. Otto hook contracts (outbound persistence) — needed at W3/W4, not before

Both hooks follow the existing discipline: kept **DISABLED between windows**, enabled by Otto only for
the test/dev window (same as `curated-import` / `case-access`). I deliver the client side; Otto
authors + enables the hook.

### Hook 1 — Review status (W3, Gap 5). Extend `case-access` or add `case-review`.

| Action | Request | Response |
|---|---|---|
| `get_review_status` | `{ caseId }` | `{ caseId, reviewStatus: 'draft' \| 'reviewed' }` (default `draft` if unset) |
| `set_review_status` | `{ caseId, reviewStatus: 'draft' \| 'reviewed' }` | `{ ok, caseId, reviewStatus }` |

- Column: **`cases.review_status`** (already provisioned). Idempotent; the flag is the only mutation.
- Authz: same verified-session gate as `case-access`; only the case owner (or an authorised HR reader)
  may read/set. No effect on the deterministic roadmap.

### Hook 2 — Spend (W4, Gap 2). New `case-spend` server hook over the provisioned `case_spend` table.

| Action | Request | Response |
|---|---|---|
| `add_spend` | `{ caseId, amount, currency: 'EUR'\|'NOK', category, incurredOn, responsibleParty, note?, requirementKey? }` | `{ ok, id }` |
| `list_spend` | `{ caseId }` | `{ rows: [...], totalsByCurrency: { EUR, NOK } }` — **per-currency only, no FX** |

- Table `case_spend` (provisioned): `case_id` FK→`cases` CASCADE, `case_obligation_id` FK→`case_obligations`
  SET NULL, `amount`, `currency`, `category`, `incurred_on`, `responsible_party`, `note`.
- **Small schema ask (my recommendation):** Model A has no `case_obligations`, so `case_obligation_id`
  stays NULL. To satisfy T2.2 ("spend linked to a specific requirement"), add a nullable
  **`requirement_key text`** column and store the roadmap requirement id there. Alternative if you'd
  rather not alter schema: carry it in `note` (loses queryability). Recommend the column.
- **Open decision — HR-wide visibility (prompt #6 flagged this):** `case_spend` policy is
  `requireVerifiedOwner:true`, `allowSharedWrites:false`, owner = `session_id`, so **writes are
  session-owned**. If HR must see *all* spend on a case regardless of who entered it, that is a
  **case-scoped read in the hook** (the hook reads across sessions server-side, gated on the caller
  being authorised for that case) — **not** a loosening of the table policy and **not** shared writes.
  My recommendation: writes stay session-owned; `list_spend` is case-scoped via the hook's server
  authority. **Please confirm before W4.**
