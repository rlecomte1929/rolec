# Eval — `classifier/v1.txt` (document classifier)

**Cohort:** C1-04a · **Classes:** 17 (per body of brief; titles say 12 — see Notes)
**Model under test:** `gpt-4o-mini` (default) · `gpt-4o` (escalation when confidence < 0.80)

This eval validates the document classifier prompt on 10 fixture
documents spanning the 17 classes and 5 languages (FR/NO/DE/EN/HI).
The C1-04 implementation will run a larger 60-doc held-out evaluation
once the agent runtime is wired up; this eval is the prompt-engineering
sanity check that the prompt itself works on the default model alone.

---

## Acceptance bar (Notion AIQ-490)

| Metric                                                              | Bar       |
|---------------------------------------------------------------------|-----------|
| Accuracy on the 10 fixtures with default model alone                 | ≥ 90 %    |
| Schema validation (output is valid JSON, code in enum)              | 100 %     |
| UNKNOWN emission when no class reaches confidence ≥ 0.5             | required when applicable |
| Signals field non-generic (cites verbatim phrase or layout clue)    | 100 %     |

The downstream C1-04 implementation will additionally validate:
- ≥ 95 % accuracy on a 60-document held-out fixture (5 per type × 12 types)
- Escalation to `gpt-4o` fires when default confidence < 0.80
- Returns 'UNKNOWN' rather than guessing when below 0.50 confidence

This eval doc focuses on the prompt's standalone quality — the
runtime concerns (escalation, agent_runs logging) live in C1-04.

---

## Methodology

For each fixture below:

1. Render the prompt by substituting the fixture's `{{ document_text }}`
   placeholder with the `INPUT` block.
2. Send as user message to `gpt-4o-mini` with the rendered prompt
   as the (effectively) system prompt or sole user content.
3. Capture the model's response text — it must be a single JSON
   object with no markdown fences.
4. Parse the JSON and compare against the `EXPECTED` block:
   - `code` matches exactly
   - `confidence` is in the expected band (≥ 0.85 for clear cases,
     0.50-0.85 for borderline, < 0.50 for UNKNOWN)
   - `signals` cites a verbatim phrase or layout clue from the input
5. Record results in the table.

Scoring rules:
- **Class match** = exact string equality. A near-miss
  (`EMPLOYMENT_CONTRACT` instead of `OFFER_LETTER`) is a fail.
- **Confidence band** = matches the expected qualitative band:
  - "clear" → confidence ≥ 0.85
  - "moderate" → 0.65 ≤ confidence < 0.85
  - "borderline" → 0.50 ≤ confidence < 0.65
  - "unknown" → confidence < 0.50 AND code = "UNKNOWN"
- **Signals quality** = at least one signal must cite a verbatim
  phrase from the input (not a generic reason like "looks like a
  passport"). Pass/fail.

## What to do when a check fails

- **F1-F3 class wrong (clear positives)**: the prompt's basic
  classification logic is broken. Inspect signals to see what the
  model latched onto.
- **F4 returned ACADEMIC_TRANSCRIPT instead of DIPLOMA**: the
  ceremonial-vs-data-dense disambiguation tip needs sharper language.
  Add a held-out fixture with both layouts in the same upload.
- **F5 returned PAYSLIP instead of TAX_RECORD**: the annual-vs-monthly
  distinction needs reinforcement. Strengthen the PAYSLIP-vs-TAX_RECORD
  disambiguation tip.
- **F6 returned EMPLOYMENT_CONTRACT instead of OFFER_LETTER**: the
  pre-contract-vs-contract distinction failed. The "we are pleased to
  offer" + "please countersign to confirm acceptance" pattern needs
  to be more prominent.
- **F7 returned DIPLOMA instead of ACADEMIC_TRANSCRIPT**: the model
  latched onto "IIT Delhi" as ceremonial. Reinforce that
  per-course-grade tables are the discriminator regardless of issuer.
- **F8 returned PROOF_OF_ADDRESS instead of BANK_STATEMENT**: the
  model latched onto the address. Reinforce that transaction lists
  are the discriminator.
- **F9 model returned a confident class instead of UNKNOWN**: critical
  failure. Reinforce the UNKNOWN rule and add a synthetic exemplar
  showing the refuse-pattern on truncated input.
- **F10 returned BIRTH_CERTIFICATE or VISA_STAMP instead of
  POLICE_CLEARANCE**: model confused by Indian-government issuer. Add
  a held-out POLICE_CLEARANCE fixture from a different national
  authority to drive the issuer-agnostic recognition.
- **Generic signals (e.g. "looks like an X")**: model is producing
  unfounded signals. Reinforce the "MUST cite verbatim phrase or
  layout clue" rule.
- **Output contains markdown fences (```json ... ```)**: model is
  wrapping JSON. Reinforce "no markdown code fences" rule.
