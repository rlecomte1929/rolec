# Accessibility Audit: HR Dashboard (C1-11 surfaces)

**Standard:** WCAG 2.1 AA · **Date:** 2026-05-29 · **Reviewer:** Claude (C1-11A · AIQ-500)
**Scope:** Components from this session's PRs:
- C1-11a · App shell + routing
- C1-11b · Case list (`feat/c1-11b-case-list` — merged to main as PR #169)
- C1-11c · Case detail page (5 sections)
- C1-11d · PDF viewer
- C1-11e · Bbox overlay
- C1-12 · Resolution UI (ContradictionPanel + CandidateCard + ReasonCodeForm + CorrectionHistory)
- C1-11c sub-components: Sheet primitive, CaseDetailNav, SectionShell, OverviewSection, DocumentsSection, StepsSection, ContradictionsSection, PolicySection, DocumentViewerSheet

## Summary

**Issues found:** 14 · **Critical:** 4 · **Major:** 6 · **Minor:** 4

The single biggest finding is **systemic** — the Tailwind config maps `text-warning`, `text-destructive`, and `text-success` to the **-500** color variants, which fail contrast on white backgrounds. The design tokens already define `--rp-status-{warning,danger,success}-fg = *-700` (which would pass), but the Tailwind utility classes shipped in C1-11D don't consume those. Fixing the Tailwind theme map fixes 5 of the findings at once.

The PDF viewer's canvas-only rendering leaves the actual text content invisible to screen readers — a serious finding for the document-review use case.

Touch-target sizing on the viewer toolbar (h-8 w-8 = 32px) is below the 44×44 WCAG target.

## Priority Fixes

1. **Remap Tailwind status colors to -700 variants** (findings #1, #2, #3) — single change in `apps/hr-dashboard/tailwind.config.cjs` swaps `warning.DEFAULT`, `destructive.DEFAULT`, `success.DEFAULT` from `*-500` to `*-700`. Fixes 3 critical contrast failures and the visible amber/red/green that already looks washed out at 20%-opacity fills.

2. **Render the pdf.js text layer for screen readers** (finding #5) — wrap `PdfPage` to call `pdfjs.renderTextLayer({...})` over the canvas. Adds the text content to the accessibility tree.

3. **Bump muted-foreground from neutral-500 → neutral-600** (finding #4) — one token edit. Affects body subtitles and table captions across the dashboard.

4. **Bump icon-button touch targets to h-11 w-11** (finding #8) — affects `PdfViewer` toolbar + `Sheet` close button.

5. **Add aria-rowcount + aria-live row-position to CasesTable** (finding #10) — small change inside the virtualized table.

6. **Restore focus to the contradiction title after resolve advance** (finding #12) — add `tabIndex={-1}` to the heading and ref-focus on advance.

7. **Add `aria-invalid` + permanent `aria-describedby` to ReasonCodeForm select** (finding #13) — 2-line change.

The remaining findings (#6, #7, #9, #11, #14) are minor / forward-compat and can land in a follow-up sweep.
